# AGENTS.MD: Руководство по архитектуре и кодовой базе ASMCode

Данный документ содержит исчерпывающее техническое описание архитектуры, внутренних механизмов, структур данных и неочевидных нюансов реализации проекта **ASMCode** (Intel 8080 IDE). Предназначен для автономных AI-агентов и инженеров, поддерживающих и развивающих данный проект.

---

## 1. Обзор архитектурной модели

ASMCode построен по принципу разделения графического слоя и ядра логики:
- **UI Слой**: Декларативная разметка Slint (`ui/appwindow.slint`), скомпилированная в нативный код во время сборки (`build.rs`).
- **Слой контроллера**: Связующий модуль `src/ui/mod.rs`, управляющий состоянием через структуру `IdeController`, обернутую в `Rc<RefCell<IdeController>>`.
- **Ядро функционала**: Независимые модули на чистом Rust (`syntax`, `autocomplete`, `compiler`, `editor`, `fs_manager`, `session`), не зависящие напрямую от UI-фреймворка.

```text
                   +----------------------------------+
                   |       ui/appwindow.slint         |
                   |   (Slint GUI: Window, Canvas)    |
                   +-----------------+----------------+
                                     | Callbacks & Properties
                                     v
                   +----------------------------------+
                   |          src/ui/mod.rs           |
                   | (IdeController, Event Dispatcher)|
                   +--------+--------+--------+-------+
                            |        |        |
         +------------------+        |        +------------------+
         v                           v                           v
+------------------+       +------------------+       +------------------+
|   src/syntax/    |       |   src/editor/    |       |  src/compiler/   |
| (Intel 8080 Lex) |       | (Undo/Redo Hist) |       | (asmx20, cpmemu) |
+------------------+       +------------------+       +------------------+
         |                           |                           |
         v                           v                           v
+------------------+       +------------------+       +------------------+
| src/autocomplete/|       | src/fs_manager/  |       |   src/session/   |
| (Docs, Extractor)|       | (File Tree, I/O) |       | (AppData JSON)   |
+------------------+       +------------------+       +------------------+
```

## 2. Глубокий анализ графического интерфейса (Slint UI)

Интерфейс в `ui/appwindow.slint` является наиболее сложной частью системы из-за специфических ограничений движка Slint и высоких требований к качеству рендеринга текста.

### 2.1. Двухслойный редактор кода (Dual-Layer Editor Pattern)

**Проблема**: Встроенный компонент Slint `TextInput` поддерживает ввод, выделение мышью, навигацию и буфер обмена, но отображает весь текст строго в одном цвете (монохромно). Компонент `Text` поддерживает форматирование, но не поддерживает интерактивный ввод и курсор.

**Решение**: Архитектура двух наложенных друг на друга слоев:
1. **Нижний слой рендеринга (`code_rows`)**:
   - Представляет собой виртуальную колонку строк, где каждая строка разбита на токены (`HighlightedSpan`).
   - Каждый токен имеет свой цвет: мнемоники (`#61afef`), регистры (`#d19a66`), директивы (`#c678dd`), метки (`#e5c07b`), числа (`#98c379`), строки (`#e06c75`), комментарии (`#7f848e`).
   - Использует шрифт `CaskaydiaCove NF SemiBold` с включенным курсивом (`font-italic: true`).
2. **Верхний слой ввода (`code_input := TextInput`)**:
   - Расположен абсолютно поверх нижнего слоя с идентичными координатами `x: 8px`, `y: 0px`, шириной и высотой.
   - Шрифт, размер (`root.editor-font-size`), интерлиньяж и курсив полностью идентичны нижнему слою.
   - Цвет символов установлен в практически прозрачный `#00000001` (когда подсветка активна). Это позволяет браузерному/нативному движку Slint выделять текст синим фоном (`#2b4f81`) при выделении мышью, но скрывает дублирующиеся монохромные буквы.
   - Если файл не является ассемблером (`!is-active-asm`), цвет текста переключается на обычный непрозрачный `#cdd6f4`.

### 2.2. Наклонный мигающий курсор (Italic Blinking Cursor)

Поскольку стандартный кареточный курсор `TextInput` в некоторых бэкендах Slint вертикальный и не учитывает наклон шрифта:
- Добавлен программный таймер `Timer { interval: 530ms; }`, переключающий свойство `root.cursor-visible`.
- При изменении положения каретки (`cursor-position-changed(cpos)`) вычисляются координаты `root.cursor-x = cpos.x + 8px` и `root.cursor-y = cpos.y`.
- Поверх текста рисуется отдельный прямоугольник курсора:
  ```slint
  Rectangle {
      x: root.cursor-x;
      y: root.cursor-y + 2px;
      width: 2.5px;
      height: root.editor-line-height - 4px;
      background: #89b4fa;
      opacity: root.cursor-visible ? 1.0 : 0.0;
  }
  ```
- Любое нажатие клавиши или ввод текста мгновенно делает курсор видимым (`root.cursor-visible = true`), предотвращая задержку отклика.

### 2.3. Контекстные меню и области наложения (Z-Index & Backdrop Traps)

**Критический баг, который был устранен**:
В Slint элементы, объявленные внутри вложенных контейнеров (`Layout`, `Rectangle`), изолированы в своем локальном контексте компоновки. Если поверх всего окна на верхнем уровне (`root`) повесить невидимую подложку `TouchArea` с `z: 95` для закрытия меню по клику вне его:
- Если подложка активируется по `show-context-menu`, она перекрывает ВСЁ окно, включая контейнер редактора.
- Клик по любому пункту меню редактора перехватывается глобальной подложкой, меню закрывается, а действие пункта меню никогда не вызывается.

**Правильное правило организации контекстных меню**:
1. **Меню проводника (`show-explorer-context-menu`)**:
   - Объявлено на верхнем уровне окна с `z: 110`.
   - Глобальная подложка окна имеет `z: 95`. Меню проводника лежит выше подложки (`110 > 95`), поэтому клики по пунктам меню срабатывают штатно.
2. **Меню редактора (`show-context-menu`)**:
   - Обязано находиться внутри контейнера редактора, так как вызывает методы `code_input.cut()`, `code_input.copy()`, `code_input.paste()`, `code_input.select-all()`, к идентификатору `code_input` нет доступа с корневого уровня окна.
   - Внутри редактора создана собственная локальная подложка:
     ```slint
     if root.show-context-menu: TouchArea {
         x: 0px; y: 0px; width: parent.width; height: parent.height; z: 110;
         clicked => { root.show-context-menu = false; }
     }
     ```
   - Сам прямоугольник меню редактора имеет `z: 120`.
   - Глобальная корневая подложка окна НЕ ДОЛЖНА реагировать на `show-context-menu`.

### 2.4. Виртуализация списков: ScrollView против ListView

- **ScrollView**: Компонент `ScrollView` со вложенным циклом `for item in list: Rectangle { ... }` внутри `VerticalLayout` НЕ РАСЧИТЫВАЕТ динамическую высоту `viewport-height` автоматически. Это приводит к тому, что высота контента приравнивается к 0, и список становится невидимым (как происходило с разделом Справки 8080).
- **ListView**: Всегда используйте `ListView` для динамических коллекций:
  - Список файлов в проводнике (`root.file-list`).
  - Список подсказок автодополнения (`root.suggestion-list`).
  - Энциклопедия команд процессора (`root.docs-list`).
  `ListView` нативно управляет полосой прокрутки, повторным использованием элементов и геометрией родителя.

## 3. Бэкенд и логика Rust (Модули `src/`)

### 3.1. Защита от повреждения файлов (`src/ui/mod.rs`)

**Ловушка потери данных**:
Когда пользователь закрывает вкладку файла (`on_close_active_file`):
- Если контроллер очищает только визуальные свойства UI (`ui.set_active_file_name("")`), но оставляет `ctrl.file_manager.active_file_path = Some(path)`, последующий вызов `Save` или сборки брал путь из `active_file_path`, считывал пустой буфер из `ui.get_code_text()` и перезаписывал файл на диске нулевой длиной!
- **Обязательный инвариант**:
  1. В `on_close_active_file` всегда обнулять `ctrl.file_manager.active_file_path = None;`.
  2. В `on_save_file`, `on_run_assemble_only`, `on_run_emulator` проверять:
     ```rust
     let active_name = ui.get_active_file_name().to_string();
     if active_name.is_empty() {
         return;
     }
     ```

### 3.2. Парсер синтаксиса (`src/syntax/intel8080.rs`)

- Работает строго по строкам без динамических аллокаций в горячих циклах.
- Распознает:
  - 8080 мнемоники (регистронезависимо через байтовое сравнение `to_ascii_uppercase`).
  - Директивы ассемблера: `ORG`, `EQU`, `DB`, `DW`, `DS`, `END`.
  - Регистры: `A`, `B`, `C`, `D`, `E`, `H`, `L`, `M`, `SP`, `PSW`.
  - Шестнадцатеричные константы: форматы `100H`, `0FFH`, `$100`, `0x100`.
  - Однострочные комментарии, начинающиеся с `;`.
- Формирует вектор `Vec<HighlightedSpan>`, транслируемый в структуру Slint `HighlightLine` для отрисовки.

### 3.3. Внешние инструменты компиляции и эмуляции (`src/compiler/runner.rs`)

Интеграция с нативными Windows-бинарниками:
1. **Ассемблер `asmx20.exe`**:
   - Путь по умолчанию: `C:\bin\asmx20.exe`.
   - Аргументы: `-80 -b -e <путь_к_asm>`.
   - Генерирует бинарный файл с расширением `.com` в той же директории.
2. **Эмулятор CP/M `cpmemu.exe`**:
   - Путь по умолчанию: `C:\bin\cpmemu.exe`.
   - Аргументы: `--8080 <путь_к_com>`.
   - Захватывает stdout и stderr процесса, форматирует лог с временными метками и передает в терминал IDE.

### 3.4. Управление историей правок (`src/editor/history.rs`)

- Реализует структуру с двумя стеками: `undo_stack: Vec<HistoryEntry>` и `redo_stack: Vec<HistoryEntry>`.
- Каждая запись хранит снимок текста и позицию курсора (`cursor_offset`).
- Лимит истории ограничен 200 состояниями для предотвращения разрастания памяти.
- Метод `toggle_line_comment` определяет текущую строку по смещению курсора и branchless-логикой добавляет или удаляет префикс `; `.

### 3.5. Сессии (`src/session/mod.rs`)

- Сохраняет JSON в каталог `%LOCALAPPDATA%\ASMCode\session.json`.
- Запоминает:
  - `last_open_folder`: последняя активная рабочая папка.
  - `last_open_file`: последний редактируемый файл.
  - `font_size`: выбранный пользователем масштаб текста.
  - `current_language`: язык интерфейса ("ru" или "en").
- При старте приложения сессия загружается автоматически, избавляя пользователя от необходимости повторно искать проект.

## 4. Сборка Windows бинарника и ресурсы

### 4.1. Подавление консольного окна

В файле `src/main.rs` первой строкой обязательно установлен атрибут:
```rust
#![windows_subsystem = "windows"]
```
Без этого атрибута Windows Linker по умолчанию компилирует проект в консольную подсистему (`IMAGE_SUBSYSTEM_WINDOWS_CUI`), что приводит к открытию черного окна `cmd.exe` при каждом запуске приложения.

### 4.2. Встраивание иконки в PE-файл

Для отображения иконки приложения в проводнике Windows:
1. Сгенерирован многослойный файл `ui/icons/app_8080.ico` с размерами 16x16, 32x32, 48x48, 64x64, 128x128 и 256x256 пикселей.
2. В `Cargo.toml` подключен `winres = "0.1"` в секцию `[build-dependencies]`.
3. В `build.rs` добавлен блок компиляции ресурсов:
   ```rust
   #[cfg(windows)]
   {
       let mut res = winres::WindowsResource::new();
       res.set_icon("ui/icons/app_8080.ico");
       let _ = res.compile();
   }
   ```
Это вшивает ресурс типа `RT_ICON` и `RT_GROUP_ICON` в заголовок PE-файла (`.rsrc`), благодаря чему `asmcode.exe` отображается с иконкой процессора Intel 8080.

## 5. Чеклист и правила для будущих агентов

При внесении любых изменений соблюдайте следующие строгие правила:

1. **Правило R-02 (Текстовая гигиена)**:
   - Категорически запрещено использование длинных тире (em-dash) в текстах интерфейса, документации и комментариях кода. Используйте дефис (`-`), двоеточие, запятые или скобки.
2. **Безопасность UI-потока Slint**:
   - Все UI-колбэки выполняются в главном графическом потоке.
   - Не запускайте длительные блокирующие операции внутри колбэков без индикации или используйте вызовы фоновых процессов через короткие таймауты.
3. **Безопасность работы с файлами**:
   - Никогда не вызывайте запись файла по пустому пути или при отсутствии активного открытого документа.
4. **Соблюдение масштабирования**:
   - Все базовые размеры элементов в `appwindow.slint` должны быть согласованы с общим масштабом (+40%). Высота кнопок управления должна быть не менее 34px, поля ввода 34-40px, шрифты текста редактора 15-20px.
5. **Тестирование**:
   - После любых изменений в синтаксисе или автодополнении запускайте `cargo test --manifest-path D:\Rust\asmcode\Cargo.toml`. Все 4 модульных теста должны проходить успешно.
