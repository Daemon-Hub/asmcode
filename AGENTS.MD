# AGENTS.MD: Руководство по архитектуре и кодовой базе ASMCode

Данный документ содержит исчерпывающее техническое описание архитектуры, внутренних механизмов, структур данных и неочевидных нюансов реализации проекта **ASMCode** (Intel 8080 IDE). Предназначен для автономных AI-агентов и инженеров, поддерживающих и развивающих данный проект.

---

## 1. Обзор архитектурной модели

ASMCode построен по принципу разделения графического слоя, слоя контроллеров и ядра логики:
- **UI Слой (`ui/`)**: Декларативная разметка Slint, разделенная на модульные компоненты (`components/`) и страницы (`pages/`), компилируемая в нативный код во время сборки (`build.rs`).
- **Слой контроллера (`src/ui/`)**: Централизованный контроллер `IdeController`, защищенный через `Arc<Mutex<IdeController>>`, с доменами обработчиков в `src/ui/handlers/` (`file_ops`, `editor_ops`, `view_ops`, `toolchain_ops`, `autocomplete_ops`).
- **Ядро функционала (`src/`)**: Независимые модули на чистом Rust (`syntax`, `autocomplete`, `compiler`, `editor`, `fs_manager`, `session`), не зависящие напрямую от UI-фреймворка.

```text
                   +----------------------------------+
                   |       ui/appwindow.slint         |
                   |   (Slint GUI: Window, Modals)    |
                   +-----------------+----------------+
                                     | Callbacks & Properties
                                     v
                   +----------------------------------+
                   |    src/ui/handlers/*.rs          |
                   | (IdeController, Event Handlers)  |
                   +--------+--------+--------+-------+
                            |        |        |
         +------------------+        |        +------------------+
         v                           v                           v
+------------------+       +------------------+       +------------------+
|   src/syntax/    |       |   src/editor/    |       |  src/compiler/   |
| (Lexer, Colors)  |       | (Undo, TextOps)  |       | (Kit, Runner)    |
+------------------+       +------------------+       +------------------+
         |                           |                           |
         v                           v                           v
+------------------+       +------------------+       +------------------+
| src/autocomplete/|       | src/fs_manager/  |       |   src/session.rs |
| (Docs, Extractor)|       | (Files, UndoDel) |       | (AppData JSON)   |
+------------------+       +------------------+       +------------------+
```

## 2. Графический интерфейс (Slint UI)

### 2.1. Панель вкладок (TabBar) и многодокументный режим
- Компонент `TabBar` (`ui/components/tab_bar.slint`) расположен между деревом проводника и правой панелью.
- При переполнении доступной ширины активируется горизонтальный скролл (`Flickable`).
- Для каждой вкладки отображается иконка типа файла, название, маркер изменений (`*`), значок закрепления (Pin) и кнопка закрытия.
- Поддерживается контекстное меню вкладок `TabContextMenu` (`ui/components/tab_context_menu.slint`), позволяющее закрывать другие/сохраненные/все вкладки, копировать пути, закреплять файлы и открывать их в проводнике Windows.

### 2.2. Двухслойный редактор кода и подстрочное выделение
- **Подстрочный фон выделения**: в отличие от стандартного перекрытия текста, выделение отображается как фоновый слой под глифами символов.
- Полукруглые края выделения реализованы через `border-radius: 2px` на фоновых плашках выделения.
- **Цветовая палитра токенов**: полностью исключен белый цвет из кодовой подсветки. Для каждой синтаксической роли (мнемоники, регистры, директивы, метки, числа, строки, комментарии) назначены контрастные тона в темах Catppuccin Mocha и Cyberpunk 2077 Red.
- **Моноширинная сетка**: шрифт `CaskaydiaCove NF SemiBold` обеспечивает строго одинаковую ширину каждого глифа, гарантируя, что курсор мыши и текстовая каретка позиционируются без дрейфа.

### 2.3. Всплывающее контекстное меню с фиксацией координат
- Контекстные меню редактора, проводника и вкладок позиционируются по абсолютным экранным координатам клика мыши (`click-x`, `click-y`).
- Меню редактора зафиксировано относительно области видимости и не прокручивается при скролле текста.
- Логика открытия меню гарантирует, что одновременно может быть активно строго одно контекстное окно.

### 2.4. Выпадающие подменю по наведению (Flyout Submenu)
- Пункт меню «Вид > Цветовая тема» открывает вложенное подменю справа от основного выпадающего списка.
- Для предотвращения случайного схлопывания меню при перемещении указателя между родительским пунктом и подменю реализована буферная зона наведения (`hover-bridge`).

### 2.5. Модальное окно настроек (SettingsDialog)
- Расположено по центру окна с полупрозрачным фоном-затемнением (`z: 150`).
- Клик по самому телу модального окна изолирован через `TouchArea`, предотвращая случайное закрытие.
- Элементы управления внутри разделов центрированы по вертикали для эстетичного отображения.
- Вкладка «Тулчейн (Сборка)» предлагает радио-переключатель между встроенным pure-Rust движком и внешними утилитами.

## 3. Бэкенд и логика Rust

### 3.1. Двойной тулчейн и отказоустойчивость (`src/compiler/`)
- **`kit_engine.rs`**:
  - Чистая Rust-реализация ассемблера Intel 8080 на основе крейта `intel-8080-kit`.
  - Транслирует исходный код в исполняемый бинарный образ CP/M `.COM` (базовый адрес `0x0100`).
  - Встроенная виртуальная память 64 КБ (`KitMemory`) и эмулятор процессора 8080 с перехватом системных вызовов CP/M BDOS:
    - Вызов `0x02` (C_WRITE): вывод одного символа из регистра E.
    - Вызов `0x09` (C_WRITESTR): вывод строки из памяти по адресу DE до терминального символа `$`.
    - Вызов `0x00` (P_TERMCPM): корректный выход из эмулятора.
- **`runner.rs`**:
  - Метод `assemble_file(file_path, toolchain_type, custom_asmx)` проверяет режим тулчейна.
  - Если выбран внешний бинарник (`toolchain_type == 1`), но файл отсутствует или путь пуст, система генерирует предупреждение, записывает его в лог и автоматически вызывает `assemble_file_builtin`.
  - Аналогичный безопасный откат реализован для `run_in_emulator(com_path, toolchain_type, custom_cpmemu)`.
  - В строке состояния IDE выводится заметный жёлтый статус предупреждения.

### 3.2. Менеджер истории отмены и редактор (`src/editor/`)
- Модуль `undo.rs` (`UndoManager`) обеспечивает гранулярную фиксацию правок текста.
- Устранена проблема стирания всего файла: посимвольный ввод группируется в логические блоки изменений.
- Модуль `text_ops.rs` работает напрямую с байтовыми срезами `&[u8]`, обеспечивая высокую производительность при удалении слов (`delete_word_left`), переключении комментариев и расчете смещений.

### 3.3. Отмена удаления в проводнике (`src/fs_manager/explorer.rs`)
- При удалении файлов или папок через проводник объект не уничтожается безвозвратно, а перемещается во временный каталог корзины приложения (`trash_bin`).
- Пользователь может отменить удаление через `Ctrl+Z`, работающий в контексте проводника.
- Если удаляемый файл был открыт в одной из вкладок, система предупреждает пользователя специальным модальным окном.

### 3.4. Персистентность сессии (`src/session.rs`)
- Файл конфигурации: `%LOCALAPPDATA%\ASMCode\session.json`.
- Сохраняемые поля:
  - `last_open_folder`: рабочий каталог проекта.
  - `last_open_file`: активный файл при закрытии.
  - `open_tabs`: полный список открытых вкладок.
  - `editor_font_size`, `editor_font_italic`, `cursor_blink`, `tab_size`.
  - `active_theme_id`: выбранная цветовая тема (0 - Catppuccin, 1 - Cyberpunk).
  - `current_language`: язык интерфейса ("ru" или "en").
  - `toolchain_type`: режим тулчейна (0 - встроенный, 1 - внешний).
  - `compiler_path`, `emulator_path`: пути к внешним бинарникам.
  - `large_file_optimizations`, `large_file_soft_limit_mb`, `large_file_hard_limit_mb`.

## 4. Сборка и ресурсы Windows

- **Подавление консольного окна**: атрибут `#![windows_subsystem = "windows"]` в `src/main.rs` исключает появление нежелательного окна `cmd.exe`.
- **Встроенная иконка**: файл `ui/icons/app_8080.ico` компилируется в PE-заголовок через `winres` в `build.rs`.

## 5. Чеклист и правила для будущих агентов

1. **Правило R-02 (Текстовая гигиена)**:
   - Категорически запрещено использование длинных тире (em-dash) в текстах интерфейса, документации и комментариях кода. Используйте дефис (`-`), двоеточие, запятые или скобки.
2. **Асинхронность тяжелых операций**:
   - Любая компиляция, запуск эмулятора или диалог выбора файла (`rfd::FileDialog`) обязаны выполняться в отдельном потоке (`std::thread::spawn`), возвращая результаты в UI через `slint::invoke_from_event_loop`.
3. **Безопасность тулчейна**:
   - Никогда не полагайтесь на безусловное наличие внешних бинарников в системе пользователя. Всегда обеспечивайте автоматический откат на встроенный `kit_engine` с информативным предупреждением.
4. **Тестирование**:
   - При любых изменениях запускайте `cargo test` и `cargo clippy -- -D warnings`. Все тесты (18 модульных и 3 интеграционных) должны проходить успешно.
